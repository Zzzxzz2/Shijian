# 执行可靠性与历史追溯

更新：2026-09-13。延续现有测试平台，新增取消、超时、中断恢复与冻结输入，没有更换执行引擎或增加依赖。

## 使用与行为

项目中选择用例，设置执行时限（1–3600 秒，默认 300 秒）再运行。时限从开始执行计算，不含排队；套件和调度沿用默认值。详情页可取消活动执行，终态展示原因、已完成结果和未完成数量，并可查看或导出报告。

| 状态 | 含义 |
|---|---|
| queued / pending | 等待开始 |
| running | 正在执行 |
| done / failed | 正常结束 / 平台执行异常 |
| cancelled | 用户取消 |
| timeout | 达到本次执行总时限 |
| interrupted | 服务退出或重启导致执行中断 |

每条结果先落库再通知页面。取消和迟到结果通过条件更新保护终态；服务启动时将遗留活动记录标为中断，不自动重放可能产生副作用的请求。`summary.total` 是计划数量，`skipped` 是未完成数量；通过率以计划数量为分母，因此通过 1 条、未完成 1 条显示 50%。

创建执行时冻结用例、断言、项目 URL 与认证配置。手动、标签、套件、手动触发调度和定时调度均覆盖。执行使用冻结输入；旧记录的名称与断言不随用例编辑或删除改变。失败重跑创建新执行，使用当前用例并生成新快照，便于展示修复前后差异。

快照沿用项目现有 AES-GCM 加密保存，公开接口和报告屏蔽常见密码、Token、认证头与敏感查询参数。历史终态没有快照时明确提示未记录，不伪造历史。

## 边界与下一步

当前适用于单进程服务；多 worker 或分布式部署前需要任务所有权与租约，不能直接共享本实现的启动恢复规则。取消只停止平台继续执行，不能撤销目标系统已完成的操作。队列仍在内存中，重启选择明确中断而非持久化续跑。

快照脱敏识别常见字段，不保证识别任意业务响应里的秘密。部署需要配置现有 `API_KEY_ENCRYPTION_KEY` 并备份，开发默认密钥不适合生产；更换密钥需先安排历史数据迁移。没有增加新密钥体系。

下一阶段优先基于实际运行规模补充执行耗时与队列监控；出现多实例需求再做持久化队列。当前不引入分布式架构、自动续跑或新权限模型。
