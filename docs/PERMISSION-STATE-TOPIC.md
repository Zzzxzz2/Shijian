# 权限与状态流转测试专题

本专题使用随项目提供的本地任务管理靶场，展示规则建模、负向测试、缺陷定位、修复和回归闭环。用例保存在 [permission-state-cases.json](../examples/permission-state-cases.json)，沿用平台 Workflow 执行与报告。

## 决策表与状态转换

| 用例 | 规则与预期 |
|---|---|
| AUTH01 | 未登录访问受保护接口：401 |
| AUTH02 | 所有者修改自己的任务：200，并核对内容 |
| AUTH03 | 其他普通用户修改任务：403 |
| AUTH04 | 普通所有者删除任务：403，删除仅管理员可用 |
| AUTH05 | 管理员删除任务：204，再查询为 404 |
| AUTH06 | 普通用户访问管理列表：403 |
| AUTH07 | 其他普通用户修改任务状态：403 |
| STATE01 | todo → doing → done → archived：逐步成功并断言状态 |
| STATE02 | todo → done 跳步：400 |
| STATE03 | done → doing 回退：400 |
| STATE04 | archived → doing 恢复：400 |
| STATE05 | 非法状态枚举：422 |
| STATE06 | 直接归档、重复归档：按现有规则成功 |

每条 Workflow 自行登录并创建所需任务，避免依赖其他用例的执行顺序；用例包含测试设计与标签。状态修改与普通修改统一要求所有者或管理员，删除仍仅限管理员。保留现有直接归档及重复归档的规则。

## 真实缺陷与复测

| 阶段 | 本地运行 | 结果 |
|---|---|---|
| 修复前基线 | 项目 6，运行 38 | 13 条：9 通过、4 失败 |
| 失败用例复测 | 项目 6，运行 43 | 4 条全部通过，diff 显示 4 条新通过 |
| 全专题回归 | 项目 9，运行 45 | 13 条全部通过 |

两个根因位于 `target-system/main.py`：

1. 状态接口只有登录校验，未检查任务所有权，其他用户修改返回 200。补充与普通修改一致的所有者/管理员校验，返回 403。
2. 非法流转的错误消息将 Pydantic 请求对象当字典读取，抛出异常造成 500。改为读取 `body.status`，恢复约定的 400；三条非法转换用例同时恢复。

没有放宽失败断言。新增 `tests/test_target_state_policy.py` 在仓库内临时数据库中验证允许/拒绝以及拒绝后状态不变。靶场原有用于安全演示的 SQL 注入入口保持原有定位，本专题不宣称靶场已安全加固。

## 复现

先启动平台（隔离数据库）、靶场 8013。将已有平台账号放入本次终端环境变量后执行：

```powershell
$env:SHIJIAN_BASE_URL='http://127.0.0.1:8010'
$env:SHIJIAN_TARGET_URL='http://127.0.0.1:8013'
$env:E2E_ADMIN_USERNAME='<本地平台账号>'
$env:E2E_ADMIN_PASSWORD='<本地平台密码>'
python scripts/run_permission_state_topic.py
```

脚本只接受本机地址，自动准备公开靶场演示用户，创建专题项目、导入 13 条用例、执行并等待结束。有业务断言失败时退出码非零，证据写入 `test-results/permission-state/run-{id}.json`。重复运行创建新的项目和结果，不覆盖前次证据。也可通过平台 JSON 导入用例；需先按脚本准备靶场账号。

## 面试展示顺序

先解释权限决策表和状态图规则，再打开基线报告展示越权与错误码异常；定位两个根因，展示失败重跑的 4 条新通过和全量 13 条通过。最后修改一条用例再查看旧执行快照，说明历史证据为什么可信。结合取消/超时后的部分结果，展示测试平台自身的可靠性测试。

本专题覆盖代表性的规则组合，不等于完整渗透测试或全业务覆盖；并发修改、权限变更时的在途请求与大规模压力测试仍可继续扩展。
