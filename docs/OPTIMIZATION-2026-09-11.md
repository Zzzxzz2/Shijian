# 试剑 3 成熟度优化与交接报告

日期：2026-09-11。范围仅为本仓库；保留 FastAPI、SQLite、原生 SPA、React 报告页和现有执行引擎。

## 1. 我如何理解试剑 3

它已经超出普通 CRUD：项目认证注入、API/UI 执行、Workflow 变量传递、Contract 断言、Mock 录制回放、Schema 多模式生成、调度与历史报告共同构成一个本地自动化测试平台。适合用作测试工程师作品集和小规模回归工具。主要短板不是功能数量，而是入口、统计口径、错误证据与复测流程之间存在断点。

## 2. 评估方式与主要发现

先阅读项目结构、README、配置、执行引擎、路由与前端实现，再启动真实后端和自带靶场。主应用使用独立的 `backend/shijian_review.db`，不以原业务数据库进行破坏性验证。随后实际操作登录、项目、用例、Schema、执行与报告，并运行后端和端到端验收。

| 优先级 | 发现 | 处理 |
|---|---|---|
| 高 | 邮箱用途 JWT 可被误当作登录 Token | 登录鉴权排除带 purpose 的 Token |
| 高 | 编辑复杂用例可能丢失 Workflow、Contract 或扩展字段 | 保留原内容，复杂内容提供完整 JSON 编辑 |
| 高 | 正在执行的记录允许删除；重复 case_id 可重复执行 | 运行中删除返回 409；创建执行时去重 |
| 高 | 访客与正式账号状态残留导致入口缺失或 401 循环 | 清理状态、恢复导航、访客显示清楚的使用指引 |
| 中 | Workflow 相对 URL 与失败步骤证据不完整 | 复用 URL 解析，记录每步请求、响应、断言与耗时 |
| 中 | 旧 E2E 只检查步骤数量，即使断言失败仍可全绿 | 增加四步全部通过断言；失败返回非零退出码 |
| 中 | 生成用例数量被当作已覆盖端点数 | 保存独立端点基线，以唯一端点与已保存用例关联计算 |
| 中 | 只有 401/400 响应定义的 Schema 仍生成 200 预期 | 优先成功响应，无成功定义时采用明确的状态码 |
| 中 | error 在历史回归与通过率中被遗漏 | pass→error 算退化，error→pass 算修复，分母包括 error |
| 中 | 类型大小写与标签子串匹配造成筛选错误 | 兼容旧类型大小写，匹配完整标签 |
| 中 | 切页旧请求、WS 与轮询可能覆盖当前结果 | 路由/请求身份检查，结果合并和连接清理 |
| 中 | 分页后编辑调度可能漏掉未显示的已选用例 | 保留并展示分页/筛选外的原选择 |
| 中 | React 报告过期登录误报不存在，登录后白屏 | 验证会话并订阅真实路由状态，保持报告目标 |
| 低 | 本地时间显示偏移，统计离开请求返回 405 | 两套前端统一 UTC 解析；兼容 sendBeacon POST |

## 3. 修复了哪些 Bug

上表列出的项目均已落地。还修正了并发 Loading 提前消失、HTML 属性引号转义、零值丢失、表单清空后旧 body/header 未移除、弹窗没有居中布局、项目分页末页判定与最近执行状态失真。项目卡片/列表的用例数和最新执行信息来自数据库实际聚合。

历史差异增加“状态变化”，避免把 error→fail 当成未变化。报告保留完整响应，Workflow 报告包含各步骤证据，便于区分环境故障、权限预期错误和真正的接口缺陷。

## 4. 原有功能的改进

- 用例编辑保持向后兼容；复杂用例使用 JSON 编辑而非强行塞进不支持的表单。
- 用例与执行历史每页 50 条，支持翻页和筛选重置；调度已有选择不会被分页截断。
- 运行页共享结果渲染，WS 与轮询互为补偿；离开页面时清理连接与定时器。
- Schema 覆盖率区分“生成候选”“保存用例”“执行通过”，删除用例后覆盖率随之下降。
- React 开发代理与 Nginx 配置补齐返回原生 SPA 的资源路径；开发时可用 BACKEND_URL 指定后端。
- 通过率将执行错误计入分母；雷达图名称改为实际统计的“测试类型数量”。

## 5. 新增能力及价值

### 失败用例重跑

报告页直接筛选失败/错误并仅重跑仍存在的失败用例。复用现有执行创建路径及权限检查，不引入第二套引擎。价值是把“发现 → 定位 → 修正 → 复测 → 历史证明”连起来。

### 原生 SPA 的 Schema 工作入口

项目内粘贴 OpenAPI JSON，选择基础、边界、安全或全部模式，预览候选、勾选保存，并查看端点覆盖明细。复用原有后端能力，仅增加必要页面与独立端点基线。

覆盖率定义：当前 OpenAPI 基线中至少存在一个带对应 coverage_key 的已保存用例的端点比例。不是代码覆盖率，不保证参数组合完整，也不表示接口通过测试。已有项目需重新解析一次 OpenAPI 才建立新基线；未建立时保留 Simple 模式。

## 6. UI / UX 改善

保持现有页面体系，新增共享 platform.css：统一阅读行距、数字对齐、焦点提示、禁用态、弹窗高度与滚动、窄屏导航和长内容换行。项目页增加三步流程引导；执行历史显示可读摘要；运行页强调结果筛选、历史基线和复测入口；Schema 页明确下一步操作及统计口径。

实际检查了桌面和 390px 宽度报告，修正小屏历史状态标签逐字折行。没有使用 Image 2.5，没有把本轮变成设计稿或换皮工程。原生亮色与 React 暗色风格仍有差异，尚未完成完整设计系统统一。

## 7. 工程结构

新增职责明确的 page-schema.js、共享交互样式及 React 时间解析小工具。继续使用既有 API、执行器、SQLAlchemy 和测试框架，没有新增依赖。数据库仅增加 schema_endpoints 字段，沿用现有 SQLite 兼容迁移。

增加聚焦真实回归的后端测试与轻量 Node 检查；加强 React 直达报告测试和主 E2E 的结果断言。没有拆解所有大文件或重写状态管理，以避免扩大风险。

## 8. 决定暂不做的内容

- 不迁移整站到 React，不重做执行框架：收益不足以抵消回归成本。
- 不加入缺陷管理、需求管理、更多 AI Provider：现阶段完善测试闭环更有价值。
- 不强做 Perf 压测与分布式队列：需要资源隔离、取消、配额和可靠任务状态设计。
- 不生成视觉参考图：真实页面调整已能直接解决问题。
- 不调用真实收费 LLM/SMTP，不部署外网：没有必要为本地质量验证引入凭据与外部副作用。

## 9. 仍有不足

- 单实例 SQLite 与进程内执行任务，服务异常退出后的任务恢复尚未系统实现；不宣称生产级高可用。
- Perf 仍是占位。参数组合覆盖、断言质量、业务需求覆盖还没有独立度量。
- Suite、Mock 等后端能力在原生 SPA 的可发现性仍不足；复杂用例 JSON 编辑需要技术背景。
- 调度选择器的新候选来自当前列表页；已有选择可保留，但大型项目需要专门的跨页搜索选择器。
- 长时间压力测试、并发性能基准、数据库故障注入、所有跨页竞态组合尚未覆盖。
- React 仍有部分接口失败后降级显示的旧逻辑；大文件、日志规范和统一错误恢复可继续渐进整理。
- 删除关联数据完整性、报告敏感响应脱敏策略值得下一阶段专项检查；当前报告用于本地授权查看，分享前应检查内容。
- Docker/Nginx 配置本轮未在真实容器中运行，不能据此宣布生产部署验证完成。

## 10. 下一阶段优先顺序

1. 任务生命周期：启动时识别中断执行、超时、取消和恢复，补故障注入验收。
2. 测试资产完整性：用例版本/快照、历史报告可追溯、删除关联行为和备份恢复。
3. 统一工作台入口：把 Suite、Mock 和报告导航整合到项目流程；再考虑大型项目选择器与设计规范。
4. 有明确需求后再实现真实 Perf 和外部 CI 质量门禁，不用功能数量替代可靠性。

## 11. 面试最值得展示的亮点

建议用 8–10 分钟展示：导入只有 401/400 定义的 OpenAPI → 查看未覆盖端点 → 保存一个候选观察覆盖率变化 → 执行并展开预期/实际 → 修改错误预期 → 仅重跑失败 → 历史显示新通过。重点解释为什么覆盖率不等于通过率，以及如何避免“测试脚本全绿但业务断言失败”。

随后展示 Workflow 登录/创建/读取/越权删除链路，说明变量捕获、权限负向断言和失败步骤证据；再选择 Mock 回放或 Contract 结构验证补充一种能力。最后展示针对实际缺陷补充的回归测试，而不是只报用例总数。
