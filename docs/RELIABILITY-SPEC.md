# 运行可靠性与追溯规格

## 目标与授权范围
基于用户已确认的三项优先改进：任务中断/超时/取消、执行快照、权限与状态专题。继续单实例 SQLite，沿用已有依赖，不自动重放被测请求。

## 验收条件
- queued/pending/running 是活动态；done/failed/cancelled/timeout/interrupted 为终态。终态不可被迟到的执行结果覆盖。
- 启动前扫描活动记录并标记 interrupted，保留已提交结果，未完成数量单列；停止平台侧执行不保证撤销被测系统已产生的副作用。
- 手动执行支持 1–3600 秒执行总时限，默认 300 秒（不含队列等待），套件/调度默认同值。取消须 editor 权限，幂等，跨项目隔离。
- 每条结果提交后才发送完成事件；终态报告明确原因和未完成数量。
- 所有创建入口在入队前冻结用例与项目 URL/认证配置；使用已有 AES-GCM 保存，公开接口仅返回常见凭据脱敏后的快照。用例修改/删除后旧报告仍使用原名称和断言。
- 旧终态没有快照时明确显示未记录，不回填伪造的历史；旧活动任务直接中断，不补跑。
- 提供可导入的权限/状态流转用例、规则矩阵、实际结果及已知靶场缺陷；不为了全绿放宽断言。

## 实现与结构
backend/models.py/database.py/schemas.py 增加兼容字段；services/run_history.py 负责冻结与读取；executor.py 维护终态和逐条持久化；现有路由和 SPA/React/HTML 报告呈现新增信息。tests/ 保存回归，docs/ 保存专题。

## 风格
复用现有 async SQLAlchemy 与 Pydantic，例如 `await db.commit()` 后再启动后台任务；不新建执行引擎，不增加依赖。

## 实施顺序
1. 快照与兼容迁移，覆盖所有创建入口；2. 生命周期与故障测试；3. 页面终态/取消/快照展示；4. 真实专题执行与全量回归。

## 命令与验证
根目录：`python -m pytest -q -p no:cacheprovider`、`node tests/frontend_maturity_check.cjs`。
frontend/react-app：`npm run build:spa-css`、`npm run build`、`npx playwright test`。
真实验证使用仓库内独立数据库和本机 8010/8013 服务，检查取消慢请求、总时限、重启恢复、修改用例后的历史与新执行区别。

## 边界
Always：保留现有改动，更新文档，测试鉴权和竞态，使用隔离数据库。
Ask first：多实例/分布式改造、真实外部系统副作用、变更产品方向。
Never：重置业务数据库、提交凭据、把失败断言改绿、明文暴露快照中的已识别凭据。
公开脱敏是常见键名和已识别值的防护，不声称能识别任意业务秘密；加密沿用现有密钥管理，开发默认密钥不用于生产。
